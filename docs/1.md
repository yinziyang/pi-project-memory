## 1. 做什么，不做什么

这是基于固定 Claude-Mem 版本派生的项目级知识系统，不是全机器会话库，也不是 Markdown 加字符串匹配的正式存储方案。
复用的 SessionStore、SessionSearch 及其必要依赖作为自包含构建产物随包提供，保留上游许可证与固定来源信息，不需要消费者检出验证仓库或启动完整 Claude-Mem Worker。

已经接通的使用链是：

```text
可信宿主提交来源 → 私有 SQLite 归档
    → 实施及独立验证 → 宿主批准精确输入
    → 持久 attempt → 后台生成 → 完整响应私有落盘
    → 未审核输出 → 宿主审核完整知识投影
    → 暂停读取并持久停用 → 发布当前 SQLite／Markdown／descriptor
    → Pi 刷新 → 搜索、阅读全文 → 重启后继续读取当前发布
```

“实施及独立验证”和“公开审核”是可信人或受控宿主的责任，不是模型自评。
代码检查批准结构、来源、字节摘要、对象快照、版本和状态一致性，不能凭这些结构证明业务事实真实、证据充分或内容已经去敏。
模型、capture 请求和模型响应均不能自行授予批准权。

本文核心闭环默认不会自动抓取会话，也不会自动判定任意代码修改已经验证、自动审核输出或自动提交 Git。
后续 N01/N02 基础片增加可信 HOME 显式启用的过滤私有归档与 Git/worktree 观察，当前使用契约见 [自动私有归档](automatic-capture.md)，独立验收状态见 [剩余能力](remaining-work.md)。
写宿主接受显式提交及批准，这是当前可用入口，不依赖模型主动记住调用保存工具。
旧草案中的自动会话补采、任务检查点、压缩上下文注入、分支影响自动分析和 TUI 综合状态条不属于本文原核心闭环验收，不用后续基础接线改写此前证据。

## 2. 哪些数据随项目发布

精选 SQLite 是公开知识的唯一真源，Markdown 只是从同一当前快照生成的阅读视图，不支持手改 Markdown 回写数据库。
私有 SQLite 是原始来源、job、attempt、完整响应、批准、输出审核及修订历史的权威记录，不复制进项目公开库。

```text
项目根目录/
├── .project-memory/
│   ├── curated.json
│   ├── knowledge.sqlite
│   ├── .publication.json
│   └── md/
│       ├── README.md
│       ├── .export-manifest.json
│       ├── 项目概况/
│       ├── 领域规则/
│       ├── 代码导航/
│       ├── 开发操作/
│       ├── 设计决策/
│       ├── 排障经验/
│       └── 项目约定/
└── .project-memory-paused       # 仅更新未完成时存在的停用标记。

项目目录之外的用户私有目录/
├── private.sqlite
└── private.sqlite.owner        # 以及 SQLite 实际需要的已知 sidecar。
```

只将完整、成功发布的 `.project-memory/` 作为项目知识交付，包含精选数据库、描述、Markdown 和自有清单。
不发布私有工作库、会话原文、完整模型响应、私有证据定位、审核人、历史修订或凭据。
`.project-memory-next` 和 `.project-memory-retained-*` 是更新或显式恢复过程的暂存／保留资源，不是当前发布，不应当作成功知识包分发。
存在持久停用标记时不能把旧目录宣传为当前有效发布。

新机器读取已有知识不需要原作者的私有数据库或生成账号，也不需要把原始会话导入本机。
读取仍需要 Pi、Node、Bun、本包及可信 PATH 中的 Python 3 与 Git，正式读取的 checkout 观察也由 Python supervisor 隔离运行。
当前 Python 验收版本为3.13.2，nonGit 项目仍支持，不要求初始化 Git 仓库，生成账号不是读取公开知识的前置条件。

## 3. 七类知识与分类责任

| 分类 | 内容 |
|---|---|
| 项目概况 | 项目目的、已落地能力、技术栈和模块职责。 |
| 领域规则 | 业务术语、状态流转、允许操作和重要约束。 |
| 代码导航 | 入口、模块、关键符号和实际调用流程。 |
| 开发操作 | 经验证的构建、启动、测试、迁移和调试方法。 |
| 设计决策 | 已采用的方案、明确决策来源、理由和适用边界。 |
| 排障经验 | 实际症状、触发条件、已确认根因、修复与复验。 |
| 项目约定 | 已有明确依据的配置、兼容、错误处理与测试约定。 |

生成提示要求模型建议七类分类，建议存入私有 `metadata.categorySuggestion`。
缺失或非法建议不猜默认类，宿主可以查看 suggested、missing、invalid 状态，但必须在输出审核时显式确认最终 category。
分类建议不等于审核通过，不会自动进入公开库。

每条公开知识都有稳定 `knowledgeId`、当前 `revision`、适用范围、公开来源和公开验证依据。
标题、正文或分类变化不需要另建一个按聊天时间命名的主题。
Markdown 按分类和稳定 ID 保存正文，首页提供标题链接，分类迁移或失效后不留下旧位置的有效正文副本。

## 4. 准入、更新和失效

### 输入批准

`capture` 只表示来源已私有归档，不表示允许发给模型。
未经实施的计划、仅讨论或仅声称“测试通过”的内容不得借此进入提炼。
可信宿主核对实施对象和独立期望后，单独批准可以发送的精确 public-safe 字节，不是把整轮原文简单清洗后直接发送。

批准绑定实际 source ID、来源原字节及身份、project、批准 ID、实施对象的 scope／version／contentDigest 和验证依据。
发送前重新读取当前对象快照并校验批准，缺失、撤销、来源不符或快照过时均零请求、零 attempt。
原样身份不 trim、不做 Unicode 归一化，BOM 和非 BMP 字符不应被解析器悄悄改写。

### 生成与输出审核

发送前持久登记 attempt，正文只来自最终加载的批准字节，不回退私有原文。
完整响应先私有落盘，随后事务性 apply 为待审核输出，模型的 verified 字段或合法 JSON 均没有批准效力。
SDK 完整 length／error 结果也留私有记录并拒绝有效 apply，不因输出碰巧能解析就认定生成完整。
SDK 逻辑响应与模型输出不等于逐字节保存原始 SSE wire。

输出审核绑定完整 projection、稳定身份、适用范围、公开来源及 evidence，宿主负责核对结论与证据对应和公开字段去敏。
原始响应、私有证据和审核人不进入公开投影。

### 当前修订

新实施及验证结论替代旧结论时，更新同一知识身份的当前修订，私有历史用于追溯，不导出流水账。
只有新建议而没有验证时，不用建议覆盖旧知识。
如果旧实现已经失效，则先暂停并撤出旧知识，即使新结论尚未验证也不能为了保留答案继续展示旧结论。
全部失效可以发布合法空快照，搜索正常返回空集合，而不是把空库误报为损坏。

这里的“当前”指宿主选定且完成审核发布的内容代，不表示系统会自动发现所有代码、分支或环境变化。
宿主必须在实际对象变化时更新当前快照并触发必要失效。

## 5. Pi 中怎样读取

正式入口为 `src/curated/pi-extension.mjs`，构建后为 `dist/curated/pi-extension.mjs`，包导出名为 `local-project-memory/pi-extension`。
根包旧 Markdown 原型 API 保留兼容，但不是这里描述的正式插件或数据库实现。

```sh
# 在本包目录执行。
npm ci
npm run build
# 在目标项目根目录执行，并使用实际包目录的绝对路径。
pi -e /你的包目录/dist/curated/pi-extension.mjs
```

本任务没有替用户进行全局安装或修改现有 Pi 配置。
插件按 `ctx.cwd` 读取固定 `.project-memory/curated.json` 与 `knowledge.sqlite`，不向上搜索，不扫描其他项目或私有工作库。
项目必须已由 Pi 判为可信，公开目录由可信宿主独占，描述文件不是模型可以更改的路径选择器或审核凭据。

`curated.json` 只包含 `version:1`、原样 project 和 64 位小写十六进制 generation，由发布流程生成，不用数据库文件 SHA 或手写占位值代替。
缺文件、非法描述、旧未审核库、损坏或内容代不匹配时，工具明确不可用，不返回伪空结果，也不回退 last-good。

| 工具／命令 | 行为 |
|---|---|
| `memory_search` | 默认 5 条、最多 10 条，返回带 scope 的候选和本实例 UUID。 |
| `memory_read` | 只接受当前周期搜索返回的 UUID，保留范围、分类、公开来源、公开依据、可读全文和稳定引用。 |
| `memory_checkpoint` | 仅显式启用私有采集且宿主已选任务时保存五字段与 revision CAS，未经审核，不批准或公开知识。 |
| `/memory-task` | 可信固定命令 new、status、unlink、select UUID revision、resume UUID revision，不接受路径或批准字段。 |
| `/memory-status` | 显示当前持久累计、公开总量及匹配当前代的 READY 索引数量，未知不伪造零，不启动 writer。 |
| `/memory-capture pause` | 停止接收并确认自动 owner 回收后才允许手动接管私有库，不等于永久修改配置。 |
| `/memory-refresh index` | 仅可信宿主显式修复当前配置的派生索引，不下载模型或授予发布权限。 |
| `/memory-refresh pause` | 先使工具不可用，取消并确认旧 reader worker 回收，供可信宿主更新。 |
| `/memory-refresh` | 显式加载当前已发布快照并生成新的候选周期，不接受项目、路径或代参数。 |

公开引用为 `{version:2, project, generation, knowledgeId, revision}`，数字 observation rowid 仅用于同代内部定位，不承担跨发布身份。
旧引用不能借新库中碰巧相同的 rowid 读取另一个主题，旧 UUID 也不能跨项目、会话或刷新周期复用。
实际插件处理 startup、new、resume、fork、reload 和 shutdown 生命周期，先清理旧实例，再安装新的当前快照。
不修改其他扩展的 active tools，也不把全部知识直接塞进系统上下文。
检查点只是未审核的私有自述，SDK 可能将工具参数保留在原会话，不得提交秘密，当前祖先关联与有界恢复契约见 [任务检查点](task-checkpoints.md)。

## 6. 检索不是 Markdown grep

当前正式插件复用 Claude-Mem 的 SQLite SessionSearch，包括 FTS 与其中文等无分词脚本的 SQL substring 支路，并保留检索相关性顺序。
不把“关键词检索”说成每次只执行纯 FTS，也不把中文支路的存在描述为 Markdown includes 实现。

E5／Chroma 已接入正式 currentReaderRuntime，显式配置后自动重建派生索引，包含真实本地模型、Chroma、generation 与稳定身份检查的专项独验。
缺失或过时代索引只能明确使用当前 SQLite 关键词结果，旧向量编号不得跨代水合。
匹配代中的坏候选明确报错，不伪装成正常零匹配。
后台 namespace 预算与 FIFO 注入有效性两 P2 已修复并独立复审关闭，正式索引与 Pi SDK 组合及六套完整旧回归均已独验，不把受控 dense adapter 或单组绿色当作整体完成。
历史裸 E5 top1 红门禁及 q04／q10 退位记录保留，不能用本轮状态与生命周期测试声称通用检索质量已全部通过。

## 7. 写宿主、发布和恢复

可执行写入口位于 `dist/authoring/`，使用方式、私有 JSON 请求格式和审批字段详见 [可信写宿主说明](authoring-host.md)。
实际使用通过独立 `supervise.py` 管理 Bun 进程，不把需要 `bun:sqlite` 的写库入口直接放进 Node Pi 主事件循环。
生产 SDK adapter 使用正常公开 SDK API 懒初始化配置和认证，默认选择 `openai-codex/gpt-6-luna`，也保留只允许本机地址的 HTTP provider 边界。
不能直接把任意公网 endpoint 填进本机 HTTP 入口。

发布步骤不能省略：

1. 实际执行 `/memory-refresh pause`，确认命令完成、无 SDK 安全错误，所有协作 reader 均已回收。
2. 向可信写宿主发送 `pause-confirmed`，持久建立 `.project-memory-paused`，重启插件也不能加载旧代。
3. 按需 invalidate 已失效知识，再登记有新验证依据的输出审核。
4. `publish` 构建当前 SQLite、七类 Markdown、descriptor 和完整自有清单，校验后一次 Linux renameat2 交换整套目录。
5. 只有确认提交、完成必要清理并解除已知归属的暂停标记后，实际执行 `/memory-refresh`。

构建、交换或清理失败保持停用，`commit-unconfirmed` 不能被解释成“未提交”，不能盲目回滚或恢复旧答案。
重开宿主后通过 `status.publication` 和显式 `recover` 核对完整快照、私有归属 ledger 与当前 generation，再完成提交或保留未完成 stage。
未知文件、手改内容、错误 stage 根、链接或未知 marker 拒绝接管，不静默删除。
确认属于自己的部分构建可以保留到 retained 目录后重新发布，不把它作为当前知识，也不凭进程退出就删除归属不明的数据。

私有目录必须与项目目录物理分离，不能互相包含，宿主在创建资源前验证，不把“Git 忽略”当作可在公开目录里存私有工作库的授权。
重开错项目、无绑定旧库或坏元数据拒绝收编。
`status` 在 SQL 边界分页，默认每集合 100 行，limit 为 1–1000，读取者必须处理 next／hasMore，不能将单页当作全部状态。

## 8. 后台与资源边界

前台只等待必要的本地扫描或持久回执，不等待慢模型完成，生成完成并经审核发布后新知识才可见，不承诺零等待。
闭环测试实际扣住 provider 响应，确认下一轮 Pi prompt 已完成且 dispatching 回执已持久。

传输失败或取消后状态可能为 unknown，unknown 不自动重发，重启仅恢复已落盘 response_ready，不自动消费 queued。
TERM、KILL 或本地超时都不能证明远端已经停止或停止计费，也不承诺端到端 exactly-once。
数据库、事务或可信 checkpoint 故障不能被吞成普通 unknown／invalid_response 后继续用未知连接，必须传播并统一停服。

Node 读取 bridge 的启动与安装共享 5000ms，请求为 10000ms，停止先 TERM、200ms 后必要时 KILL，再最多等待 1000ms 确认 close。
5000ms 不含前置文件 I/O、生命周期排队、旧桥回收或诊断落盘，不是整个 session_start 的总时限。
写宿主默认请求 10000ms、运行 3600000ms，实际总预算和停止升级由独立进程监督入口承担，细则见写宿主文档。
同步 SQLite／Python 不被 AbortSignal 实时抢占，不用 Promise.race 提前返回假装底层已经停止。

完整回收与库级 close 成功是不同事实，已回收进程可以带 cleanup 异常，但不能被伪报为仍有活资源。
close 未确认时保留 PID、所有权与资源状态，确认停止后才清理仍可能被使用的文件。
公开工具错误只提供固定安全码，不带原异常、stack、cause、私有路径或内容。
可信宿主的有界诊断另存 HOME 下 `.local-project-memory-diagnostics/curated.json`，目录 0700、文件 0600，不随项目发布。
这不是防御同 UID 恶意程序的权限沙箱，可信宿主不能把私有审批通道交给模型。
